# БД/API — область SemOr14

Статус передачи: реализация ещё не начата. Формат событий и весь вход/выход описаны в `contracts/README.md`, `contracts/event.schema.json`, `contracts/upstream-websocket.md`. Рабочая ветка — `work/data-api`.

Следующая задача: реализовать SQLite-хранилище append-only событий и всех снимков узлов, пакетную запись с idempotency по event_id, корреляцию запросов/ответов по run_id/session_id/request_id, чтение с фильтрами и отдельный аудит полного HTTP входа/выхода. Затем импортировать исторические JSONL без потери полей и исходных временных меток. Хранить все данные/логи, скрывая секреты.

Предлагаемая схема: events (исходный JSON и метаданные), node_snapshots (состояние каждого узла с ссылкой на событие), http_exchanges (полные запрос/ответ, статус, время), schema_migrations. Это проектное решение, SQL-миграций и работающего сервера пока нет.

Сервис БД не управляет оборудованием. Подключение к Куполу и отправка control остаются в agent/. Интеграция двух веток — после реализации клиента доставки у агента.
