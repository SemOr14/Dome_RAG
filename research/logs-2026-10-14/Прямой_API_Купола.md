# Прямой доступ к Куполу

Проверено 26.10.2026 по живому серверу `http://62.118.24.234:48765` и его [OpenAPI](http://62.118.24.234:48765/openapi.json).

## Что доступно напрямую

| Метод | Адрес | Назначение |
|---|---|---|
| `GET` | `/api/telemetry` | Текущий сводный снимок без авторизации |
| `POST` | `/api/chat` | Сообщение помощнику: `{"message":"..."}` → `{"reply":"..."}` |

Страница `/static/index.html` обращается именно к этим двум методам. Телеметрия обновляется каждые 2 секунды. Полный API описан в `/openapi.json`, есть интерфейс `/docs`.

Есть также административные `/admin/state`, `/admin/stage`, `/admin/reset`. Они относятся к управлению сценарием и защищены паролем; запрос без него к `/admin/state` вернул `401`. Их нельзя считать участническим API Купола.

В опубликованной схеме **нет** отдельных методов `get_node_status`, `control_power_line` и т. п. Это внутренние функции помощника, вызываемые через `/api/chat`. Публичного прямого API для подробной диагностики каждого узла и управления оборудованием пока не обнаружено.

## Структура `/api/telemetry`

| Поле | Значение |
|---|---|
| `solarKw`, `windKw` | Текущая генерация в кВт |
| `windState` | Состояние ветрогенератора |
| `lines`, `lineNames`, `lineStates` | 8 линий: нагрузка в кВт, имя, состояние; элементы с одинаковым индексом относятся к одной линии |
| `battery` | `soc` (заряд, %), `mode`, `error`, `grid` |
| `temp`, `hum`, `co2` | Температура, влажность, CO₂ |
| `printer`, `cnc` | `status`, `progress`, `remainMin`, `file`, `hold`, `holdReason`, `online`; у принтера может быть `bedClear` |
| `diesel` | `on`, `kw`, `fuel` |
| `forecastStartHour`, `fSun`, `fWind` | Час начала и 12 значений прогноза солнца (%) и ветра (м/с) |
| `gameTime` | `day`, `hour` — внутреннее время сценария |

Сервер не отдаёт в этом ответе метку времени измерения. При сохранении снимков нужно добавлять собственное время получения. Показания и формат могут измениться на следующих этапах игры.

## Карта подсистем

По ответам помощника выявлены внутренние `node_id` (это **не** публичные HTTP-маршруты и не подтверждённые аппаратные `device_id`):

- Энергия: `solar_panels_01`, `solar_inverter_01`, `battery_01`, `wind_turbine_01`, `dizel_1`, `fuel_tank_01`, `smart_panel_01`.
- Производство: `printer_3d_01`, `cnc_01`, `material_inventory_01`, `equipment_cooling_01`.
- Климат: `climate_sensor_01`–`03`, `air_quality_sensor_01`, `smoke_detector_01`–`02`, `fume_extraction_01`, `supply_ventilation_01`, `dome_sealing_01`.
- Теплицы: `thermal_insulation_01` (ФабЛаб, 3D-принтер), `thermal_insulation_02` (Химлаб).
- Среда и безопасность: `weather_station_01`, `seysmo_01`, `radiation_sensor_01`, `chem_sensor_01`, `fire_suppression_01`, `access_control_01`.
- Вода: `water_pump_01`, `water_tank_01`, `water_filter_01`.
- Связь и автоматика: `radio_01`, `backup_comms_01`, `edge_compute_01`, `network_link_01`, `dome_automation_01`.

Эта карта взята из ответов помощника в `Диалог_с_помощником.md`; независимой проверки полного списка через прямой API нет. В телеметрии проверены только поля и связи, перечисленные выше.

Регламент (раздел 8.1) подтверждает четыре крупных контура: энергетика, телеметрия и связь, производство, микроклимат. Он не приводит `node_id` и адреса API. Регламент упоминает просмотр исторических данных, но в опубликованном HTTP API метода для архива нет. Разделы 8.3 и 10.1 ограничивают применение программ и агентов в игре предоставленными или прямо разрешёнными интерфейсами; возможность использовать собственный скрипт во время финала стоит уточнить у организаторов. На этапе подготовки регламент разрешает любые программные библиотеки и инструменты (10.5).

## Примеры без сайта и чата

PowerShell:

```powershell
Invoke-RestMethod 'http://62.118.24.234:48765/api/telemetry' | ConvertTo-Json -Depth 8
```

Python:

```powershell
python .\исследование_купола\kupol_read.py
python .\исследование_купола\kupol_read.py --json
python .\исследование_купола\kupol_read.py --watch 2
```

Скрипт делает только запросы чтения к `/api/telemetry`.
