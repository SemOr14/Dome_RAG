# Матрица инструкций агенту

Локальная спецификация 0.1. Не подключена к исполнительному контуру. Факты дня, ограничения API и предложенные меры различаются по полям источников и coverage.

## Общие шлюзы допуска

- **G01:** Текущая подтверждённая роль/смена team, каталог и allowlist; operator_controls не исполняются агентом.

- **G02:** Все критические входы присутствуют, конечны, свежи и пригодны по времени/зоне; UNKNOWN не превращается в NORMAL.

- **G03:** Разрешённое действие, строгие типы и вложенные диапазоны; integer не bool; проверка NaN/Infinity.

- **G04:** Заново проверены физические/технологические предусловия, активные защиты и последствия для зависимых систем.

- **G05:** Нет конфликтующей или непрояснённой отправки; назначен единственный владелец ресурса.

- **G06:** Намерение устойчиво записано до обычной управляющей отправки; event_id/request/session/incident связаны.

- **G07:** Бюджет попыток и переключений доступен, восстановлен после рестарта; дедлайн не основан на неверном clock domain.

- **G08:** Есть проверяемый эффект и срок профиля; уже достигнутую цель считать no-op, новые эффекты подтверждать новыми данными.

## R01. Штатные события — сохранять без управляющей реакции

**Условие:** Проход GRANTED без тревоги, обычное изменение числовых показаний, ожидаемый переход состояния, подтверждение своего действия.

**Режим:** RECORD_ONLY; **приоритет:** P3

**До решения проверить:**

- Нет отдельного признака угрозы или нарушения задачи.

- Событие не конфликтует с активным инцидентом.

**Инструкция:**

- Сохранить исходную запись и обновить проекцию.

- Связать ответ с запросом; закрыть верификацию только по подходящим данным.

- Не создавать кризис из каждого изменения.

**Не делать:**

- Не вызывать LLM и не тревожить Оператора для каждого journal/change.

- Не удалять сырые повторы вместо дедупликации уведомлений.

**Подтверждение результата:**

- Полный payload сохранён; новых control и сообщений Оператору нет.

**Покрытие:** observed


## R02. DEGRADED — качество данных, а не автоматический отказ оборудования

**Условие:** Изменение sensor_state на DEGRADED без подтверждённого физического нарушения.

**Режим:** MONITOR; **приоритет:** P2

**До решения проверить:**

- status, online, updated_at, время получения.

- Используется ли источник сейчас ПЛК/производственной задачей.

**Инструкция:**

- Открыть интервал сниженного качества.

- Снизить пригодность его доказательств; при критическом использовании перейти в DIAGNOSE.

- При возвращении OK закрыть интервал только после проверки стабильности.

**Не делать:**

- Не сбрасывать ошибки и не калибровать устройство лишь из-за слова DEGRADED.

- Не считать confidence независимым измерением.

**Подтверждение результата:**

- Оценена актуальность и влияние на текущие решения.

**Покрытие:** observed


## R03. null, отсутствующее поле и изменение типа

**Условие:** Поле стало null, пропало, получило неожиданный тип или NaN/Infinity.

**Режим:** DIAGNOSE; **приоритет:** P1

**До решения проверить:**

- Наличие ключа отдельно от его значения.

- Версия/каталог, предыдущие наблюдения этого поля, источник и частота.

**Инструкция:**

- Сохранить исходное представление; пометить пригодность поля.

- Всегда-null историческое поле не объявлять новым кризисом.

- Не использовать непригодное поле для команд; искать допустимый резерв.

**Не делать:**

- Не подставлять 0 вместо неизвестной мощности, false вместо неизвестной тревоги или числовую ёмкость по умолчанию как измеренный факт.

- Не считать bool числом.

**Подтверждение результата:**

- Решение учитывает UNKNOWN; поле и причина непригодности сохранены.

**Покрытие:** observed


## R04. Замороженная телеметрия и общий сбой времени

**Условие:** Пакеты приходят, но данные не продвигаются; UNKNOWN/online=false; узел или весь поток отстаёт.

**Режим:** DIAGNOSE; **приоритет:** P1

**До решения проверить:**

- Монотонное время приёма, последовательность кадров, прогресс updated_at.

- Домен часов и clock_offset; качество соседних источников.

**Инструкция:**

- Отделить потерю канала от физического отказа.

- Запретить решения об отсутствии угрозы на старых данных.

- Сервисное восстановление только по текущему service_actions и утверждённой процедуре; проверить новый поток.

**Не делать:**

- Не считать максимум updated_at среди всех одновременно зависших узлов признаком свежести.

- Не перезапускать общий сервис вслепую.

**Подтверждение результата:**

- Есть несколько новых валидных кадров; время и состояние восстановлены.

**Покрытие:** not_observed_this_day


## R05. Сопоставление CO₂ с задержками и общей причиной ошибки

**Условие:** Один CO₂ выше других, быстрый рост или предполагаемое правило 2 из 3.

**Режим:** DIAGNOSE; **приоритет:** P1

**До решения проверить:**

- Одна зона и единицы.

- reading_delay_s, возраст, sensor_state, online, дрейф и история на соответствующее время.

- Группы общей причины: одна шина/питание/помеха не дают независимые голоса.

**Инструкция:**

- Сравнивать синхронизированные измерения: задержанный датчик в t сопоставлять с историей другого в t-delay.

- Отдельно оценить текущую среду: историческое согласие не доказывает текущую безопасность.

- При недостатке текущих данных — UNKNOWN; защиту не снимать; разрешённые защитные действия выбирать по текущему контексту.

**Не делать:**

- Не объявлять свежие 2600 ppm ложными только потому, что значения 15/30 минут назад были 700.

- Не называть быстрый скачок безусловно физически невозможным.

**Подтверждение результата:**

- Для вывода указаны интервалы измерения и действительно независимые доказательства.

**Покрытие:** observed; эпизоды DAY-05


## R06. Подтверждённая неисправность основного CO₂ и восстановление

**Условие:** Есть достаточные доказательства ошибки конкретного CO₂; источник выбран ПЛК или уже вызвал удержание.

**Режим:** CONDITIONAL_CONTROL; **приоритет:** P1

**До решения проверить:**

- Пройдены R05 и проверка текущей среды.

- Есть подходящий здоровый резерв; права set_data_trust/set_primary_sensor/reset_interlock известны.

- Установлен активный incident_id и текущий IL_CO2.

**Инструкция:**

- Пометить только доказанно ошибочный параметр.

- Дождаться новой телеметрии с точной пометкой.

- Выбрать проверенный резерв и подтвердить выбор.

- При устранённом условии снять только IL_CO2 и подтвердить ARMED.

- Отдельно продолжить нужный станок, проверить состояние и прогресс.

**Не делать:**

- Не лишать интерлок последнего пригодного источника.

- Не отправлять всю цепочку сразу и не продолжать её после отказа шага.

- Не считать ложный сигнал отсутствием реального простоя.

**Подтверждение результата:**

- Подтверждены доверие/выбор источника, ARMED, снятие hold и продолжение реального задания.

**Покрытие:** observed; эпизоды DAY-05


## R07. Вероятный реальный рост CO₂

**Условие:** Текущие пригодные источники/наблюдения подтверждают рост; либо высокая опасность не опровергнута.

**Режим:** PROTECTIVE_CONTROL; **приоритет:** P0

**До решения проверить:**

- Свежие данные и состояние приточки, доступные режимы, шторм/дым/герметизация.

**Инструкция:**

- Сохранить причину и доказательства.

- По разрешённому сценарию восстановить приток/подходящий режим; не конфликтовать со штормом или дымом.

- При отсутствии расхода запросить физическую проверку; дать краткое значимое сообщение.

- Resume только после подтверждённого восстановления среды и разрешения удержания.

**Не делать:**

- Не снимать защиту, чтобы улучшить метрику простоя.

- Не блокировать автоматику по спокойным задержанным датчикам.

**Подтверждение результата:**

- Не только speed_pct, но фактический расход, отсутствие relevant alarm и устойчивая динамика CO₂.

**Покрытие:** not_observed_this_day


## R08. Риск конденсата

**Условие:** IL_CONDENSATE, высокая RH или малый запас до точки росы.

**Режим:** DIAGNOSE; **приоритет:** P1

**До решения проверить:**

- Сопоставимые RH/T/Tросы, свежесть, зоны, независимые наблюдения.

**Инструкция:**

- Считать риск возможным до проверки.

- При доказанной ошибке одного параметра — точечная пометка; при реальном/неясном риске сохранить удержание и выполнить допустимую процедуру осмотра/просушки.

**Не делать:**

- Не объявлять RH=99% ложной лишь потому, что температура воздуха не падала.

- Не игнорировать температуру поверхностей и общий отказ источников.

**Подтверждение результата:**

- Условие исчезло по пригодным данным; только затем interlock recovery и resume.

**Покрытие:** not_observed_this_day


## R09. Ложный COMPLETED webhook

**Условие:** webhook_state=COMPLETED, но state/real_state=PRINTING, прогресс или Z изменяются, задание не окончено.

**Режим:** RECORD_AND_VETO; **приоритет:** P1

**До решения проверить:**

- Свежие state/real_state, progress_pct, file_name, Z и последовательность кадров.

**Инструкция:**

- Записать расхождение и сомнительность конкретного канала статуса.

- Оставить печать в работе; запретить разблокировку бокса и объявление готовности.

- Если Оператор уже направлен за деталью — немедленно исправить сообщение.

**Не делать:**

- Не открывать бокс, не перезапускать принтер и не отменять правильную печать ради согласования флагов.

**Подтверждение результата:**

- Бокс остаётся закрытым; завершение позже подтверждено несколькими подходящими признаками.

**Покрытие:** observed; эпизоды DAY-04


## R10. Штатное завершение, охлаждение и выдача детали

**Условие:** Подтверждённое завершение задания и запрос на получение детали.

**Режим:** TASK_WORKFLOW; **приоритет:** P2

**До решения проверить:**

- Идентичность задания, отсутствие движения/печати, прогресс, термосостояние по утверждённой процедуре, дверь/замок.

**Инструкция:**

- Записать завершение как рабочий этап.

- Разблокировать конкретный замок только после всех предпосылок; проверить замок.

- Получить релевантное сообщение Оператора о снятии детали, проверить дверь и состояние стола.

- Новое задание запускать только после повторной проверки готовности.

**Не делать:**

- Открытая дверь/bed_clear в модели не доказывают физическое удаление детали.

- Горячий стол и небезопасный доступ не разрешаются голосованием статусов.

**Подтверждение результата:**

- Задание, деталь и действие Оператора связаны; нет нового запуска на занятый стол.

**Покрытие:** observed; эпизоды DAY-06


## R11. E09 и другие ошибки инвертора

**Условие:** error=true, error_code=E09 или иной код; генерация/MPPT меняются.

**Режим:** DIAGNOSE_THEN_APPROVED_RECOVERY; **приоритет:** P1

**До решения проверить:**

- Текущий код и состояние; погодные данные лишь косвенные.

- Действующая разрешённая процедура диагностики электрической части и восстановления.

**Инструкция:**

- Оценить влияние на питание и сохранить ошибку.

- Не объявлять изоляцию ложной по сходству с прошлым туманом.

- Сброс допустим только после выполненной процедуры устранения/подтверждения допустимости; отсутствие данных не заменяет это условие.

- После допуска — один ограниченный шаг с проверкой ошибки, MPPT и генерации при наличии освещения.

**Не делать:**

- Не делать reset_error по одному таймеру или пропавшему датчику влажности.

- Не повторять до успеха.

**Подтверждение результата:**

- Новые данные подтверждают ожидаемый режим без повторной ошибки; при повторе — остановить попытки и эскалировать.

**Покрытие:** observed; эпизоды DAY-01


## R12. Низкая генерация без доказательства отказа

**Условие:** PV/ветер дают мало или ноль.

**Режим:** MONITOR; **приоритет:** P2

**До решения проверить:**

- Время окружения, освещённость/ветер, состояние источника, MPPT, ошибки и нагрузка.

**Инструкция:**

- Отделить ночь/штиль/ограничение генерации от отказа.

- Записать естественные изменения без восстановления исправного оборудования.

- При несогласованности — диагностика, не автоматическое включение канала.

**Не делать:**

- Не лечить ночь командой enable_mppt.

- Не включать ветер при штормовом запрете.

**Подтверждение результата:**

- Отклонение объяснено наблюдаемыми условиями либо открыта проверяемая гипотеза.

**Покрытие:** observed


## R13. Нежелательное потребление резервной линии

**Условие:** На линии есть устойчивое потребление, несовместимое с подтверждённым назначением.

**Режим:** CONDITIONAL_CONTROL_AND_OPERATOR; **приоритет:** P1

**До решения проверить:**

- Текущая карта нагрузок и отсутствие разрешённой нагрузки.

- Мощность, ток, состояние, утечка; пригодность измерений; последствия изоляции.

**Инструкция:**

- Зафиксировать подозрение, не подменять его диагнозом утечки.

- Если линия не критична и изоляция разрешена, выключить один раз и проверить эффект.

- Физический осмотр/ремонт — уполномоченному Оператору/специалисту.

- Возврат только по релевантному результату осмотра и проверенной процедуре.

**Не делать:**

- Не считать линию 8 пустой навсегда по одному прошлому дню.

- Не давать агенту право ремонтировать силовой клеммник.

**Подтверждение результата:**

- Проверены линия и последствия, после восстановления — нормальное фактическое потребление.

**Покрытие:** observed; эпизоды DAY-02


## R14. Срабатывание защиты, перегрузка, перенапряжение

**Условие:** TRIPPED/RCD_TRIP, IL_OVERCURRENT/IL_OVERVOLT/IL_INV_OVERLOAD или связанные аварии.

**Режим:** PROTECT_AND_ESCALATE; **приоритет:** P0

**До решения проверить:**

- Точная линия/узел и причина, реальная нагрузка, зависимые потребители, текущий интерлок.

**Инструкция:**

- Различить аппаратную и программную защиту.

- Сохранить состояние, проверить причину и передать допустимую физическую проверку.

- Возврат питания — после доказанного устранения причины по утверждённой процедуре.

**Не делать:**

- Нулевой ток уже отключённой линии не доказывает устранение неисправности.

- Не включать автоматически по истечении 180 секунд и не циклировать реле.

**Подтверждение результата:**

- Условие устранено, возврат разрешён; новая телеметрия подтверждает питание без повторной аварии.

**Покрытие:** not_observed_this_day


## R15. Энергетическое планирование

**Условие:** Ожидаемый дефицит или снижение SOC угрожают задаче, но авария не подтверждена.

**Режим:** PLANNED_CONTROL; **приоритет:** P1

**До решения проверить:**

- Потоки инвертора, SOC/напряжение/ёмкость с отметкой достоверности, доступность сети/дизеля, производственный план.

**Инструкция:**

- Проверены выбранный источник, реальные потоки и сохранение критических потребителей.

**Покрытие:** observed; эпизоды DAY-03, DAY-08


## R16. Мигание света и общий шум датчиков

**Условие:** Неожиданные переключения света и/или согласованные помехи датчиков.

**Инструкция:**

- Открыть гипотезу общей причины; временная корреляция не доказывает причинность.

- При разрешённой пробе сначала подтвердить аварийный свет, затем изолировать некритичное освещение; один владелец и бюджет воздействий.

**Не делать:**

- Не считать три коррелированных датчика тремя независимыми голосами.

**Подтверждение результата:**

- Независимо подтверждены освещение, динамика помех и отсутствие вредных последствий; гипотеза не повышается до факта без основания.

## R17. Дым и квитирование с защитным эффектом

**Инструкция:**

- По умолчанию считать угрозу неразрешённой.

- Дать краткое сообщение; сохранить защитную реакцию.

- Квитирование, отменяющее автоматическое пожаротушение, не является обычной отметкой о прочтении: допускается только отдельным разрешённым сценарием с сильным подтверждением ложности конкретного события/зоны.

**Подтверждение результата:**

- Сверены zone/event_id и актуальные защитные состояния; неизвестность не выдаётся за безопасность.

## R24. БД недоступна — сохранение и управление развязаны

- После восстановления все подтверждённые локальные события доставлены без дубликатов, с пропусками/потерями, если были, явно отмеченными.
