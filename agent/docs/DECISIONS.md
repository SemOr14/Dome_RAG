# Принятые решения

Решения, принятые при реализации автономно (без участия человека), и отступления от ТЗ. Решения пользователя
отмечены словом «пользователь».

## Окружение и процесс

1. **Корень репозитория** — каталог проекта; `TZ_kupol.md`, `TZ_kupol_addendum.md` и PDF регламента лежат в нём и
   входят в историю.
2. **Окружение**: `.venv` в корне (в `.gitignore`), `pip install -e ".[dev]"`. Ничего не ставится глобально
   (пожелание пользователя). Python ≥ 3.11 (разработка на 3.12).
3. **Зависимости**: runtime — `pydantic>=2`, `pyyaml`, `httpx`, `rich`, `streamlit`; dev — `pytest`, `pytest-cov`, `mypy`,
   `types-PyYAML`. Прочих инструментов (ruff и т. п.) не добавлено.
4. **Коммиты** (пользователь): от глобального пользователя git, без строк `Co-Authored-By` и без упоминания Claude.
   Сообщения на русском (Conventional Commits), один логический шаг — один коммит, только зелёное состояние.
5. **Панель** (пользователь): веб на Streamlit.
6. **LLM** (пользователь): ключа нет, режим только `mock`; реальные вызовы не проверялись.

## Архитектура

7. **`engine.py` сверх структуры ТЗ.** Главный цикл вынесен в класс `Engine` с методом `step()`: его используют CLI
   (`simulate`, `run`, `benchmark`) и панель. Так цикл тестируется без процессов и экрана.
8. **Время.** Симулятор живёт на виртуальном времени, `advance` двигает его; `--speed 0` — без пауз (тесты,
   приёмка, benchmark). Метки времени — UTC. В реальном адаптере `advance` ничего не делает.
9. **Единое плоское пространство имён полей** (`Telemetry.flat()`: `co2_ppm.<id>`, `lines.<имя>.power_w`,
   `temp_c_2`). Детекторы, baseline, пробы, метрики и разметка симулятора говорят на одном языке полей.
10. **Принцип «код считает, LLM объясняет».** Уверенность, вероятности гипотез, уровень реакции и допуск команд
    вычисляются кодом (`verdicts`, `response`, `guard`); LLM может только предложить гипотезы и формулировки. Придуманные
    моделью пробы вне каталога отбрасываются, вероятности пересчитываются.
11. **Агенты в пуле потоков** с таймаутом (медленная модель не останавливает опрос); в режиме `mock` — синхронно, чтобы
    прогоны были детерминированы.
12. **Guard — единственный путь команд**, включая пробы, действия агентов, человека и симулированного Оператора.
13. **Команды `needs_human` в headless** подтверждает только флаг `--auto-approve` (актёр `sim-auto-approve` в журнале).
    Без флага такие команды ждут в очереди и истекают по TTL. Для `benchmark` флаг включён всегда.
14. **Streamlit**: `Engine` крутится в фоновом потоке и создаётся один раз (`st.cache_resource`); страница
    обновляется фрагментом `st.fragment(run_every=1)`; кнопки кладут действия в потокобезопасную очередь движка.
    Тест — `streamlit.testing.v1.AppTest`.
15. **Реакция на «ложный» CO2.** Не включать вытяжку на `high` без подтверждающих признаков: максимум `low` (команда
    `vent_enable` с `auto`-классом) либо запрос подтверждения. Любой режим вытяжки, включая `high` и `off`, —
    `set_vent_mode` (`needs_human`, `costly`).
16. **Защита модели.** Режим `competition` с любым именем модели, кроме `deepseek-v4-flash`, бросает
    `ForbiddenModelError` — проверка в конструкторе и перед каждым вызовом.

## Решения по дополнению (скрытые события, вердикты, пробы)

17. **Вердикт — накопление свидетельств**: `p = σ(bias + scale·Σ ±w·0.5^(возраст/half_life))`. Масштаб 2,5 вместо 1,0
    образца (см. `ASSUMPTIONS.md`).
18. **Гистерезис вида «ложный»**: вердикт «ложный» пересматривается через `unknown` при появлении свидетельств
    «за реальный» с коэффициентом 1,25 (чтобы не метаться на границе порога). «Ложный» не закрывается навсегда
    (`watch_after_false_s` = 300 с).
19. **CUSUM — только пары и невязка баланса**, порог 14σ (почему — в `ASSUMPTIONS.md`); сброс накопления при выбросах
    более 8σ, чтобы одиночный скачок не принимался за дрейф.
20. **Baseline калибрует только шум датчиков (после вычитания линейного тренда по подокнам), разность пар (медианой) и σ
    невязки баланса.** Абсолютных уровней и ожиданий по режимам в коде нет; данные периода тревоги в baseline не
    попадают (поля с активной тревогой warning и выше блокируются). Тест `test_baseline_has_no_absolute_levels`
    проверяет, что снимок не содержит абсолютных уровней.
21. **Пробы через Guard**; ответ Оператора на вопрос пробы — свидетельство `operator`/`probe`/`video`. Выбор — по
    информативности в бюджете (`max_per_10min`, `energy_budget_wh`, `min_gap_s`). В headless вопросы Оператору
    отвечает симулированный Оператор (`--sim-operator`) по разметке симулятора.
22. **Правило двух и исключение безопасности.** Дорогое действие (`costly`) и `act_full` — не менее двух независимых
    источников свидетельств. События безопасности (`smoke`, `solder_overheat`, `operator_stop`) правило двух снимают, белый
    список и диапазоны остаются.
23. **Защита от каскада** — в Guard: после дорогого действия запас времени до минимума SoC не должен быть меньше
    `response.cascade_min_t_left_min`; иначе команда понижается (`DOWNGRADED`) и записывается.
24. **Прогноз до порога** поднимает реакцию не выше `prepare`.
25. **«Обход» и события безопасности** вызываются из панели (интерфейс человека); в headless их заменяют сценарные
    события и `--sim-operator`.
26. **Метрики по эталонной разметке** симулятора (`ground_truth.jsonl`): сигнал считается обнаружением воздействия,
    если подходящая по типу тревога появилась в окне воздействия плюс допуск `DETECT_GRACE_S` (300 с). Пересмотр
    вердикта «ложный» засчитан, если вердикт ушёл из «ложных» видов (`reclassified` или `revised`) в пределах
    `watch_after_false_s` от создания. Разметку агенты не видят.
27. **Benchmark** — отдельные процессы по сценариям и seed (по числу ядер, не более 6), LLM всегда `mock`. Числа
    детерминированы по seed.
28. **Сценарий `mixed`**: добавлена вторая печать на 2200 с, иначе принтер не работал в момент «тихого брака» (2300 с)
    и событие не проявлялось.

29. **Графики решений** — отдельная вкладка панели, а не экран по умолчанию: основной вид («Штаб») остаётся для
    быстрых решений. Историю ведёт `ChartRecorder` в движке (а не панель по снимкам), чтобы ряды не зависели от
    открытой вкладки и обновления страницы. Пороги и коридоры рисуются из конфигурации, а не дублируются в панели.
    Один график — одна ось (разные единицы — разные графики); цвета рядов закреплены за порядком, а для порогов
    используются статусные цвета с текстовой подписью.

## Соревновательный режим (Dome)

С материалами организаторов (`Dome_RAG/`) выяснилось, что реальное задание — другое: WebSocket-API с ~40 узлами,
чат Оператора, интерлоки автоматики, оценка по простоям и ложным остановкам. Поэтому добавлен новый рантайм
`src/kupol/dome/`, а прежние симулятор, ядро, панель и бенчмарк оставлены для регрессии.

30. **Новый рантайм рядом со старым** (пользователь). Прежний `Engine` построен на выдуманной модели `Telemetry`;
    40 реальных узлов с `hold_reason`, интерлоками, `data_trust` и чатом в неё не ложатся без потерь. Общее: идея
    «код считает, модель объясняет», свидетельства со взвешиванием, Guard-подобный `Gate`, журнал, mock-тесты.
31. **Управление только по явной команде** (пользователь). Чтение данных разрешено всегда; любой `control`
    (включая `post_message`) уходит в сеть лишь при `DOME_ALLOW_CONTROL=1`, который выставляет человек.
    По умолчанию `Gate` пишет `action` с `dry_run: true`. `AGENT_DRY_RUN=1` приоритетнее.
32. **Ключи** — из окружения, `.env` или файла ключей (`Dome_RAG/Keys/team_1.txt`: строки `team:` и `deepseek:`).
    Значения не печатаются и вычищаются из любой строки лога; в `start` пишется только источник.
33. **Список моделей LLM** берётся из материалов организаторов (`deepseek-chat`, `deepseek-reasoner`), а не только
    `deepseek-v4-flash`: `llm.allowed_models` в `config.yaml` и тот же список в `dome/llm.py`.
34. **Политика команд — белый список в `dome.yaml`** (узел → действие → допустимое значение), поверх `describe_nodes`.
    В нём нет `block_interlock`, `block_automation`, пожаротушения, замков дверей купола, порогов датчиков,
    загрузки файлов: аппаратные блокировки не отключаются.
35. **Опережение интерлока.** `IL_CO2` срабатывает через 60 с после начала условия (`pending_s`). Ложный выброс
    основного датчика (скорость роста > 40 ppm/с либо расхождение со *согласными* остальными) обрабатывается сразу:
    датчик помечается `UNRELIABLE`, основной меняется — станки не встают (в журнале 14.10 агент реагировал после
    остановки). Рост на нескольких датчиках — реальный: интерлок не сбрасывается, приток на максимум.
36. **`resume` — один раз и только когда причина ушла** (интерлок снова `ARMED`, значения в норме, пауза на
    «успокоение»). Три пустые попытки блокируют станок на 20 минут; `BED_COLLISION` и `FILAMENT_RUNOUT` снимает
    только Оператор.
37. **Дым: «неуверенно = реально».** Квитирование (оно отменяет автопуск пожаротушения) — только при ≥ 2 независимых
    свидетельствах ложности (CO, VOC, задымлённость, флаг датчика, слово Оператора) и без единого признака
    реального дыма.
38. **`webhook_state` не доверяем.** Завершением печати считается согласие `state`, `real_state`, прогресса и
    остатка времени; бокс открывается только после этого и остывания стола (журнал 14.10: бокс открыли при 33 %).
39. **Модель — только советчик.** `DeepSeek` в `dome/llm.py` не отправляет команд: диагностирует ситуации, которых
    нет в плейбуках, отвечает на свободные вопросы Оператора; лимиты — интервал по теме и вызовы в час; ответ в
    формате примера JSON (схема JSON путала модель); сбой — просто нет подсказки. Каждый вызов — `llm_call`.
40. **RAG без внешних зависимостей** (BM25 на чистом Python) по `knowledge/*.md`, эпизодам `events.jsonl` и записям
    жильцов; найденные фрагменты попадают в `rag_refs` решения. Локальные модели эмбеддингов не нужны.
41. **Лог агента** — отдельный `AgentLog` по формату организаторов (`agent_<run_id>.jsonl`), а не прежний
    `Journal`; формат проверяет `tools/check_agent_log.py`.

## Известные упрощения

- Реальный адаптер — шаблон; три переводчика не реализованы (по ТЗ).
- Матрица «симптом → причины» и примеры в промптах — на выдуманных данных.
- Запись журнала синхронная в основном потоке; при больших объёмах телеметрии (часы) стоит вынести в отдельный поток.
- Рантайм Dome проверен на локальном эмуляторе (правила сервера по `01_API.md` §7) и на снимках журнала 14.10;
  на живом тренировочном куполе чтение не проверялось: адрес `192.168.8.10` недоступен вне сети организаторов.
- Значения `hold_reason`, коды ошибок и параметры интерлоков взяты из документации и журнала одного дня; плейбуки
  осторожны к незнакомым значениям (не действуют, спрашивают модель/Оператора).
