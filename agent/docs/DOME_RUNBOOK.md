# Запуск агента на соревновании (Dome)

Агент — `python main.py` (или `python -m kupol dome`). Он работает без участия человека, переживает
перезапуск и сам переподключается. Подробности протокола — `Dome_RAG/01_API.md`, требования —
`Dome_RAG/03_Требования_к_агенту.md`.

## Подготовка (один раз)

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt   # или: pip install -e ".[dev]"
copy .env.example .env                                      # впишите DOME_URL / DOME_KEY / DEEPSEEK_API_KEY
```

Ключи можно не копировать в `.env`: если рядом лежит `Dome_RAG/Keys/team_1.txt` со строками
`team: <ключ купола>` и `deepseek: <ключ DeepSeek>`, агент возьмёт их оттуда (приоритет:
окружение → `.env` → файл ключей). Ключи не пишутся ни в лог, ни в git.

| Переменная | Значение |
|---|---|
| `DOME_URL` | адрес купола, по умолчанию `ws://192.168.8.10:8765` (нужна сеть организаторов) |
| `DOME_KEY`, `DEEPSEEK_API_KEY`, `DEEPSEEK_BASE_URL` | ключи и адрес API |
| `AGENT_LOG_DIR` | каталог логов (по умолчанию `logs`) |
| `DOME_ALLOW_CONTROL` | `1` — разрешить управление. **По умолчанию выключено** |
| `AGENT_DRY_RUN` | `1` — анализировать и писать в лог, ничего не отправлять (приоритетнее `DOME_ALLOW_CONTROL`) |

## Режимы

1. **Только чтение (по умолчанию).** Агент подключается, читает телеметрию и чат, принимает решения и
   пишет их в лог. Команды `control` (включая сообщения в чат) в сеть **не уходят**: в логе записи
   `action` с `dry_run: true`. Подходит для проверки на живом куполе.
2. **Управление.** `DOME_ALLOW_CONTROL=1`. Включать только по решению команды и непосредственно перед
   сменой. Любая команда проходит `Gate`: каталог `describe_nodes` → политика `dome.yaml` → защитные
   правила → отправка → проверка эффекта (`verification`).

## Проверка связи (только чтение)

```powershell
.venv\Scripts\python tools\probe_dome.py --snapshots 2 --save tests\fixtures   # auth, describe_nodes, телеметрия
.venv\Scripts\python tools\probe_llm.py "Вопрос про купол"                      # один запрос к DeepSeek
```

Если `192.168.8.10` не отвечает — компьютер не в сети организаторов (Wi-Fi купола).

## Репетиция

```powershell
.venv\Scripts\python main.py --dry-run --max-ticks 300     # 10 минут наблюдения без команд
.venv\Scripts\python tools\check_agent_log.py logs\agent_<время>.jsonl
```

Скрипт проверяет формат лога по требованиям организаторов (поля, `ref`-цепочки
`decision → action → verification`, отсутствие ключей).

## На смене

1. Запустить `python main.py` с `DOME_ALLOW_CONTROL=1` — одной командой, без ввода.
2. Агент после падения/перезапуска продолжает: состояние лежит в `state/agent_state.json`
   (память плейбуков, кулдауны, обработанные сообщения чата).
3. Остановка — Ctrl+C или SIGTERM: лог закрывается, последняя запись `stop`.
4. **Сразу после смены** отдать организаторам все `logs/agent_*.jsonl` за смену.

## Что агент делает сам, а что нет

- **Сам:** помечает врущий датчик недостоверным и меняет основной (до срабатывания интерлока), снимает
  интерлок после проверки и один раз продолжает станки, запускает файлы по просьбе Оператора, разблокирует
  бокс только после настоящего завершения печати и остывания стола, переводит инвертор в `GRID_ONLY` при
  низком SOC, сбрасывает E09 после просыхания, отключает фантомную линию 8, сбрасывает аварии устройств с
  ограничениями.
- **Никогда:** `block_interlock`, `block_automation`, пожаротушение, замки дверей купола, пороги датчиков,
  загрузка файлов, паузы станков, повтор команды без проверки результата, команды гостем или при
  устаревшей телеметрии. Список — `policy.allowed` в `dome.yaml`.
- **Просит Оператора** (коротко, один раз): физические действия (осмотр клеммника, чистка фильтра,
  замена катушки, переключение канала связи) и неопределённые случаи вроде тревоги дыма без подтверждения.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `Нет ключа купола` | проверить `.env` / `KEYS_FILE` |
| подключение не проходит | сеть организаторов; в логе `connection/disconnected` с причиной |
| роль `guest` | не ваша смена: агент ждёт и ничего не отправляет |
| агент «молчит» | режим «только чтение»: смотреть записи `action` с `dry_run` |
| хочется сбросить состояние | удалить `state/agent_state.json` (кулдауны и память плейбуков обнулятся) |
