# Допущения

Реальный API, протокол, имена полей, диапазоны команд и физика Комплекса неизвестны, поэтому всё ниже **выдумано**
(в коде помечено `# ASSUMPTION:`, в `config.yaml` — по комментарию в шапке). Что менять утром — в
`docs/MORNING_CHECKLIST.md`.

## 1. Протокол и интерфейс Комплекса

| Допущение | Где | Утром |
|---|---|---|
| Комплекс доступен по REST: `http://kupol.local/api`, пути `/telemetry`, `/history`, `/command`, токен в `KUPOL_API_TOKEN` | `config.yaml → real`, `adapter/real.py` | Узнать протокол, поправить раздел `real`; для MQTT/WebSocket заменить `_request` |
| Структура ответа телеметрии, истории и результата команды (три функции-переводчика не реализованы) | `adapter/real.py` | Дописать `map_telemetry`, `map_history`, `encode_command`, `decode_command_result` |
| Один снимок содержит: `pv_power_w`, `battery_soc_pct`, `battery_voltage_v`, `battery_temp_c`, `load_total_w`, линии щита (`on`, `power_w`), `temp_c`, `temp_c_2`, `humidity_pct`, `co2_ppm.<датчик>` (три датчика `co2_a/b/c`), `vent_mode`, `humidifier_mode`, `power_mode`, статусы `cnc/printer/solder`, `comms_ok`, время UTC | `core/models.py` (`Telemetry`) | Сопоставить в `map_telemetry`; отсутствующие поля — пустые |
| Второй датчик температуры `temp_c_2` и три датчика CO2 | `Telemetry`, `config.yaml` | Если их нет, убрать из `detectors.pair_diff.groups` и `round.pairs` |
| Опрос 1 раз в секунду (`game.tick_s`) | `config.yaml → game` | Подогнать под реальную частоту |
| Контрольное время игры 90 минут | `game.duration_min` | Сверить с регламентом перед стартом |

## 4. Пороги и детекторы

| Допущение | Значение | Где |
|---|---|---|
| Пороги warn/crit по SoC, напряжению, температуре АКБ, температуре, влажности, CO2; скачки; уклоны | см. файл | `thresholds` |
| Периоды устаревания данных, потери связи | 5 / 15 / 10 с | `detectors.stale_*`, `comms_loss_s` |
| **Порог CUSUM 14σ** вместо 5σ из образца ТЗ | 14σ, допуск 0,5σ, выбросы > 8σ отбрасываются | `detectors.cusum` |
| Прогноз до порога: горизонт, R² не ниже, окно | 900 с, 0,7, 5 мин, ≥ 60 точек | `detectors.time_to_threshold` |
| Разность пар: жёсткие пределы, уклон, коридор, подтверждение | CO2 150 ppm, температура 2 °C; 20 ppm/мин, 0,2 °C/мин; 4σ; 3 такта | `detectors.pair_diff` |
| Потеря шума, залипание, физический предел скорости | 0,1·σ; 60/120 с; CO2 40 ppm/с, температура 0,3 °C/с и др. | `detectors.noise_loss`, `freeze_s`, `max_rate_per_s` |
| Правила сверки (разности CO2, скачок, окна баланса, допуски) | см. файл | `crosscheck` |
| Параметры калибровки: окно 300 с, подокно 30 с, пол σ невязки 25 Вт, запас на σ 1,25 | см. файл | `baseline` |

**Почему CUSUM 14σ.** При опросе 1 раз в секунду порог 5σ из образца ТЗ даёт десятки ложных срабатываний за игру
(накопление по сотням отсчётов), на `quiet` выходило значительно больше одного warning в час. Порог 14σ с допуском 0,5σ
подобран по сценариям `quiet` и `hidden` (20 seed): ноль ложных срабатываний, скрытые события ловятся. На реальных
данных порог и допуск нужно подогнать.

## 7. Матрица «симптом → причины → проверка»

Априорные вероятности причин в `agents/symptom_matrix.yaml` (≈ 19 строк, см. `docs/SYMPTOM_MATRIX.md`) — оценки
для каркаса. Они нужны только как стартовые значения для Диагноста и резервного сценария; команда уточняет их по
опыту игр.

## 8. Эталонная разметка

Критерии «обнаружено»/«упреждение»/«ложное срабатывание» в `core/metrics.py` (допуск 300 с после окончания воздействия (`DETECT_GRACE_S`),
соответствие видов тревог типам воздействий) — договорённость инструмента измерения, не часть решений Штаба.
