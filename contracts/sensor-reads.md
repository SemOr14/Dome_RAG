# Чтение датчиков во время запроса LLM

Дополнение к конверту событий 1.0, без миграции БД и без изменения протокола Купола.

Модель может вызвать read-only функцию `read_sensor(node_id, fields)` перед окончательным
решением. Источник — последний доступный снимок TelemetryRepo, прочитанный в момент
выполнения функции: состояние Runner, API данных либо явно выбранный файловый пример.
API Купола передаёт измерения датчиков в телеметрии и не предоставляет универсальную
команду физического опроса; инструмент не выдумывает такую команду и не вызывает control.

- Один вызов `DomeLLMAgent.decide()` имеет общий бюджет **3 обращения**, включая
  повторные раунды модели, неверные аргументы и недоступные датчики. Бюджет локален
  запросу и не сбрасывается при исправлении JSON.
- Обращения исполняются последовательно. Четвёртое получает `limit_exceeded`, без
  чтения источника. После исчерпания бюджета функции больше не предлагаются модели;
  число раундов дополнительно ограничено кодом.
- Разрешены узлы текущего каталога, кроме чата meeting_01. `fields` — до 16 скалярных
  путей, например `co2_ppm` или `humidity_pct[1]`. Пустой список — ограниченный набор
  скалярных показаний. Секретные/служебные деревья чата и файлов не выдаются.
- Результат содержит readings, missing_fields и метаданные timestamp, observed_at,
  node_updated_at, telemetry_age_s, node_age_s, online, status, sensor_state, fresh.
  Отсутствующие данные не заменяются нулём. Без достаточных меток свежесть неизвестна;
  старые/неработающие источники явно помечаются. Чтение не меняет время кадра.
- Ошибка чтения возвращается модели как ошибка инструмента. Она не считается новым
  измерением, успешной командой или подтверждением физического эффекта.

Native function calls и результаты передаются в стандартных assistant/tool сообщениях
DeepSeek. Финальный ответ остаётся AgentDecision и проходит прежние проверки/Gate.
В llm_request сохраняются фактические инструменты и история, в llm_response — tool_calls.
Каждая попытка записывается отдельным `sensor_read` с llm_call_id, tool_call_id, порядком,
аргументами и результатом; итоговое decision дополнено `sensor_read_event_ids`.
Все записи наследуют run/session текущего EventSink; исходные данные сохраняет существующий
канал телеметрии. Для чтения аппаратное управление включать не требуется.
