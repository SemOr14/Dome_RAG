# Совместная работа

Работаем через GitHub Issues и pull request в `main`, чтобы видеть владельца задачи и не делать одну работу параллельно.

## Перед началом

1. Найдите задачу в Issues. Если её нет — создайте issue с ожидаемым результатом и списком файлов.
2. Назначьте одного ответственного. Второй участник может помогать в комментариях, но не начинает тот же участок без согласования.
3. Создайте отдельную ветку от свежего `main`, например `logs/schema-review` или `agent/reconnect`.
4. В начале работы оставьте в issue короткую отметку: что делаете и какие файлы меняете.

## Разделение участков для трёх участников

- **Журналы и данные:** сверка источников, схемы полей, графа связей и воспроизводимости анализа в `Logs/` и `research/`.
- **Агент:** поведение, надёжность, правила управления и документация запуска. Не подключайтесь к реальному куполу без отдельной согласованной задачи.
- **Документация и интеграция:** API, база знаний, проверки фактов и объединение результатов в pull request.

Роли можно менять; закрепляйте конкретные файлы и результаты за issue, чтобы участки не пересекались.

## Завершение задачи

- Коммиты делайте в своей ветке с короткими понятными сообщениями.
- Откройте pull request в `main`, укажите issue и перечислите изменённые файлы.
- Попросите одного из двух других участников проверить результат.
- После слияния закройте issue и удалите завершённую ветку.

Не коммитьте ключи, `.env`, локальное состояние агента и временные файлы. Если ключ уже попал в Git, его нужно заменить: удаление файла не стирает его из истории.
