# kupol-agent

Агент дежурного инженера для соревнования «Лига автономных систем — Купол».

Задача агента — чтобы работа Оператора не прерывалась: держать станки в работе,
отличать ложную тревогу от настоящей, упреждать угрозы и звать человека только на
физические действия.

## Запуск

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env    # заполнить DOME_URL, DOME_KEY, DEEPSEEK_API_KEY
python main.py
```

Переменные окружения читаются из окружения процесса; `.env` можно загрузить
любым удобным способом (например, `Get-Content .env | ForEach-Object { ... }`),
агент сам `.env` не парсит.

Без интерактива: ни ввода, ни окон, ни подтверждений. Остановка — Ctrl+C или SIGTERM,
при остановке пишется запись `stop` и лог закрывается.

## Что внутри

| Модуль | Роль |
|---|---|
| `dome.py` | WebSocket-клиент: авторизация, запросы, телеметрия, переподключение, лимиты |
| `model.py` | снимок телеметрии: узлы, поля, старение данных |
| `rules.py` | детерминированные правила (безопасность и производство) |
| `brain.py` | цикл: наблюдение → решение → действие → проверка |
| `llm.py` | DeepSeek: диагностика сложных случаев, текст для Оператора |
| `rag.py` | поиск по базе знаний и журналу прошлой недели |
| `agent_log.py` | лог формата требований (JSON Lines) |
| `mock_dome.py` | локальный тренажёр протокола со сценарием |

## Правила (rules.py)

- **Удержание станка** (`hold_level`): resume только после устранения причины и не
  больше одной попытки на эпизод — три пустых попытки дают ALARM на 20 минут.
- **Ложный CO₂**: если основной датчик ≥ 2000 ppm, а два других < 1200 — датчик
  помечается `UNRELIABLE`, основной переключается на исправный, `IL_CO2` снимается,
  станки продолжаются. Если растут все три — тревога настоящая: приток на 100 %,
  сообщение Оператору, станки не трогаем.
- **Деталь на столе**: после `COMPLETED` открывается замок бокса и Оператор
  просится забрать деталь; печать на занятый стол не запускается.
- **Защита линии**: `reset_protection` один раз, с проверкой тока и состояния,
  не больше двух раз на линию за 15 минут (защита от дребезга).
- **Энергия**: дизель включается при SOC < 30 %, автономности < 1 ч или дефиците
  > 400 Вт, выключается при SOC > 85 % и отсутствии дефицита.
- **Связь**: при деградации основного канала — резервный канал и просьба проверить
  патчкорд.
- **Дым**: при подтверждении — вытяжка и сообщение, без сброса; при ложном
  срабатывании — квитирование и сброс датчика (важно: не квитировать `IL_SMOKE`
  нельзя — через 60 с автоматика запустит пожаротушение).
- **Застарелые данные**: `status = UNKNOWN` или неподвижный `updated_at` —
  `reconnect` узла, а не доверие последним значениям.

## Логи

`AGENT_LOG_DIR/agent_<run_id>.jsonl`, одна запись — один JSON-объект:
`start`, `connection`, `observation` (раз в 45 с и при изменениях),
`decision`, `action`, `verification`, `message`, `llm_call`, `error`, `stop`.
Ключи в лог не попадают.

## Проверка адреса купола

```powershell
python probe_dome.py ws://<хост>:8765
```

Печатает роль, каталог прав и первый срез телеметрии. Ничего не меняет.

## Самопроверка правил

```powershell
python selftest.py
```

12 проверок на синтетической телеметрии: ложный и реальный CO₂, неизвестная причина
удержания, защита линии, деталь на столе, запуск печати, занятый стол, низкий SOC,
застывшие данные.

## Тренажёр

```powershell
python mock_dome.py
# в другом окне
$env:DOME_URL='ws://127.0.0.1:8765'; $env:DOME_KEY='test'; $env:AGENT_LLM_ENABLED='0'
python main.py
```

Сценарий: Оператор выдаёт задание на печать, принтер печатает, затем основной датчик
CO₂ показывает 3041 ppm (ложная тревога), `IL_CO2` останавливает оба станка. Агент
должен распознать сбой, снять удержание и продолжить печать, а после завершения —
открыть бокс и позвать Оператора.
