# RAG Купола

Работающий локальный поиск по базе Купола, сбор контекста с источниками и опциональная генерация диагностического предложения через DeepSeek.

База: **32 FAQ, 24 карточки ситуаций, 12 конфликтов источников**, все 13 файлов knowledge, API и доступная история за 14 октября 2026 года. Рабочая выдача использует 56 согласованных записей. Ещё 670 исходных фрагментов доступны только отдельным справочным поиском, поскольку часть исходных рекомендаций противоречит API или требует проверки.

Каждый ответ содержит: **наблюдение → интерпретация → решение → верификация → корректировка**. Верификация имеет значение `not_run`, пока отдельный агент не выполнит действие и не получит новые данные. В RAG нет исполнителя команд оборудованию.

## Запуск Windows

Требуется Python 3.11+. Из папки `rag` в репозитории:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
.\.venv\Scripts\python.exe -m rag ask "Принтер пишет COMPLETED, но продолжает печатать"
```

Установка загружает зависимости и локальную ONNX-модель. Затем поиск работает без внешнего API. Готовые индексы включены в репозиторий; веса модели в Git не включены. На новом устройстве `setup.ps1` загружает их и пересобирает индекс. Для запуска без семантических зависимостей:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1 -LexicalOnly
.\.venv\Scripts\python.exe -m rag ask "Почему resume принят, а станок на паузе?" --lexical-only
```

## DeepSeek

В `.env` указать свой `DEEPSEEK_API_KEY`. Пример без ключа — `.env.example`. По умолчанию модель `deepseek-flash`, рассуждение выключено; модель/endpoint настраиваются по разрешениям организаторов.

```powershell
.\.venv\Scripts\python.exe -m rag ask "Какие данные проверить при ложном webhook?" --llm
```

Обращение к облаку происходит только с `--llm`. При недоступности API, неполном JSON или выдуманных ссылках возвращается локальный ответ с явной причиной отказа от генерации. В поле `llm.proposal` находится предложение модели; проверка цитат не доказывает его фактическую истинность.

Модель получает отобранные записи, применимые конфликты и источники, не весь архив. Ключ не входит в контекст и журналы. Redirect авторизованного запроса запрещён. Указание `--llm` разрешает отправку вопроса и переданного контекста выбранному DeepSeek endpoint.

## Команды

```powershell
# Гибридный поиск: технические имена, BM25, локальные векторы
.\.venv\Scripts\python.exe -m rag search "Пустая резервная розетка ест пятьдесят ватт"

# Только ситуации или FAQ
.\.venv\Scripts\python.exe -m rag search "пауза" --kind situation

# Справочные фрагменты — отдельный режим, не готовые инструкции
.\.venv\Scripts\python.exe -m rag search "электрическая схема" --kind reference --include-reference

# Пакет контекста, без вызова LLM
.\.venv\Scripts\python.exe -m rag context "CO2 3000, остальные 800" --output context.json

# Новая текущая телеметрия — только явным файлом, не подставляется из истории
.\.venv\Scripts\python.exe -m rag ask "CO2 сейчас 3000, что проверить?" --observation observation.json

# Локальный API
.\.venv\Scripts\python.exe -m rag serve --port 8790

# Проверки
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m rag evaluate
```

Linux/macOS: `python3 -m venv .venv`, `.venv/bin/python -m pip install -r requirements-semantic.txt`, `.venv/bin/python -m rag build --semantic`. На этой сборке фактически проверена Windows; другие ОС не проверялись.

## HTTP API

Сервер слушает только `127.0.0.1`. `GET /health` сообщает состояние. `POST /query` принимает:

```json
{"question":"Webhook завершён, но прогресс растёт","use_llm":false}
```

Дополнительные поля: `observation`, `max_chars`. Для запросов с `use_llm=true` сервер надо запустить с `--allow-llm`. Веб-запросы с посторонним Origin отклоняются. Никаких маршрутов управления куполом и выдачи ключей нет.

Текущие наблюдения принимаются как предоставленные, но не гарантированно достоверные:

```json
{
  "received_at":"2026-10-26T17:00:00+03:00",
  "nodes":{"printer_3d_01":{"state":"PRINTING","progress_pct":33.1}}
}
```

Это пример структуры, а не живое измерение. Временная метка с часовым поясом обязательна для оценки свежести. Значения из прошлого не превращаются в текущую телеметрию.

## Устройство

- `rag/corpus.py` — проверка снимков и сборка индекса.
- `rag/search.py`, `dense.py` — BM25, точные термины, локальные эмбеддинги и объединение рангов.
- `rag/context.py` — бюджет в символах, источники, конфликты и пять этапов ответа.
- `rag/llm.py` — DeepSeek, проверка JSON/ссылок и сетевых ошибок.
- `rag/server.py` — локальный HTTP API.
- `data/knowledge_base/` — согласованные FAQ/карточки и исходные кандидаты.
- `data/sources/` — неизменённые входные документы/логи с хешами.
- `data/APPROVAL.json` — основание реализации и редакторские изменения.
- `evaluation/` — результаты проверок и отдельный набор перефразировок.

Изменение базы после сборки индекса вызывает явную ошибку. Изменение исходного снимка требует сверки карточек и обновления происхождения. `tools/import_approved.py` предназначен для первоначального импорта из согласованного проекта, а не для обычного запуска.

## Проверенный результат и границы

Локальная ONNX-модель: `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, CPU, векторы 384 измерений. Зависимости фактической Windows-сборки — `requirements-lock.txt`; переносимое требование — `requirements-semantic.txt`.

Проверены локальные тесты, поиск и реальный вызов DeepSeek. Подробности и расходы успешного тестового вызова — `VALIDATION.md`. Результаты retrieval на конечном небольшом наборе не доказывают точность любого диагноза. Исторические причины могут оставаться гипотезами; отсутствующие текущие данные обозначаются явно.

API купола не подключён. Последующее исполнение, принятие решения о допустимости действия, журнал полного агента и фактическая верификация результата реализуются отдельно.

Первоисточники интерфейса DeepSeek: [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/), [Thinking mode](https://api-docs.deepseek.com/guides/thinking_mode/). Локальные эмбеддинги: [FastEmbed](https://qdrant.github.io/fastembed/).
